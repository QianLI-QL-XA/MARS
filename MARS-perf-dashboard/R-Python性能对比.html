测试设置

两组数据同一路径、同一停机准则，仅求解器实现与 BLAS 不同。

数据

prostmat.csv 6033×102（50 control + 52 cancer）；z-score 标准化；findA = 行中心化 + thin SVD。

λ 路径

maxλ 的 95% / 85% / 75% 共 3 点（排除 65% 低 λ 病态多解区）。

算法参数

stoptol=1e-4，maxiter=10，stopmethod=fix；gap<tol 停机补丁已启用。

环境

R 4.6.1（UCRT）+ Intel MKL 2024.2.2；Python 3 + Numba v3（11 个 JIT 内核）。同一台 Windows 主机，顺序执行。

结论

  1. R(MKL) 全面领先：control 7.27s / cancer 9.26s，比 Numba v3 快 1.27× / 1.17×；较历史 Reference BLAS（135.1s / 162.3s）提速约 18×。
  2. JIT 化收效：Numba 从 11.32s / 12.04s 降至 9.24s / 10.87s（control −18%、cancer −10%）；新增 gradP（A@A.T 复用 + 稀疏感知）、proxBmain、tri 扫描、maxλ、对称 norm 等 6 个 JIT 内核，累计 11 个。
  3. 解高度一致：排除低 λ 后，obj 最大相对误差 3.4×10⁻⁶（λ1 位级一致），稀疏结构 s_off 差异 ≤1 边——差异为多解区边界的浮点分支，非实现错误。
  4. 剩余差距：R 仍快 1.17–1.27×，主因是 adaptive sieving 主循环与 Index/sub 管理的 Python 解释层尚未 JIT；换 BLAS（MKL）仍是 R 的第一性能杠杆。
